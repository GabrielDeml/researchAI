# Experiment design: Topic Can a raw per-seed file be released containing initialization attempts and misses, offspring attempts and misses, target counters, failure indicators, both scores, and per-run duplicate ratios for both algorithms? _(auto-enqueued follow-up from genetic-algorithms-2)_

**Hypothesis:** When generational and steady-state GAs are run for seeds 0 through 29 on 64-bit OneMax, deriving an independent random-number substream from each (algorithm, seed) pair will produce byte-identical per-seed records when algorithm execution order is reversed, whereas using one shared global pseudorandom stream will change at least 80% of rows in one or more of initialization attempts, offspring attempts, duplicate ratio, or either score.

## Summary
Run generational and steady-state genetic algorithms on synthetic 64-bit OneMax for seeds 0-29, then test whether reversing algorithm order preserves canonical per-seed records under pair-derived RNG streams but changes at least 24 of 30 rows in a shared-stream condition.

## Protocol
1. Use Python 3.11 with numpy==1.26.4 and matplotlib==3.8.4; use only the standard library otherwise. Run single-threaded and do not parallelize algorithm executions.
2. Define the synthetic objective OneMax on an unsigned 64-bit integer x as fitness(x) = int(x).bit_count(), with optimum 64. Set MASTER_SEED=20250308, MASK64=(1<<64)-1, population size N=64, initialization target=64 accepted unique genomes, initialization attempt cap=10000, offspring target=2048 accepted children, and offspring attempt cap=100000.
3. Use numpy.random.Generator(numpy.random.PCG64(seed_sequence)) for every RNG. Generate a random genome as int(rng.bit_generator.random_raw()) & MASK64.
4. Initialize a population by repeatedly generating genomes until 64 distinct genomes have been accepted or 10000 attempts have occurred. Count every generated genome as initialization_attempts; count an attempted genome already in the accepted population as initialization_misses. Record initialization_accepted, initialization_target=64, and initialization_failed=int(initialization_accepted<64). If initialization fails, do not generate offspring; set offspring_attempts=0, offspring_misses=0, offspring_accepted=0, offspring_failed=1, and score to the best initialized fitness, or 0 if none was accepted.
5. Define tournament selection by independently drawing two population indices with rng.integers(0,len(population)); select the higher-fitness genome and select the first-drawn genome on a tie. To create one attempted child, select two parents using two such tournaments, draw a 64-bit crossover mask with random_raw(), and form child=(parent1 & mask) | (parent2 & ((~mask) & MASK64)). Draw k=int(rng.binomial(64,1/64)); if k>0, draw k distinct bit positions with rng.choice(64,size=k,replace=False) and flip those positions in the child. Mask the result with MASK64.
6. Implement the generational GA as follows. Starting from the initialized population, build a new generation of 64 children. Each attempted child increments offspring_attempts. Reject it and increment offspring_misses if it equals any genome in the current population or any already accepted child in the new generation. Otherwise accept it, increment offspring_accepted, and update the best-ever score. Once 64 children have been accepted, replace the entire population with them and begin the next generation. Stop immediately when offspring_accepted reaches 2048 or offspring_attempts reaches 100000. Because 2048 is divisible by 64, a successful run ends at a generation boundary. Set offspring_failed=int(offspring_accepted<2048).
7. Implement the steady-state GA with the same initialization, selection, crossover, and mutation. Each attempted child increments offspring_attempts. Reject it and increment offspring_misses if it is already in the current population. Otherwise accept it, increment offspring_accepted, append it to the population, update the best-ever score, find all indices having minimum fitness in the resulting 65-member population, select one of those indices uniformly with rng.integers(0,number_of_minima), and delete that individual. Stop when offspring_accepted reaches 2048 or offspring_attempts reaches 100000. Set offspring_failed=int(offspring_accepted<2048).
8. For either algorithm, define best_score as the maximum fitness observed among all accepted initialization genomes and accepted offspring, including offspring later removed. Define duplicate_ratio=(initialization_misses+offspring_misses)/(initialization_attempts+offspring_attempts), with 0.0 if the denominator is zero.
9. Evaluate seeds 0 through 29 under two RNG-allocation modes and two execution orders. In independent mode, give each run a fresh RNG based on SeedSequence([MASTER_SEED, seed, algorithm_id]), where algorithm_id=0 for generational and 1 for steady-state. In shared mode, for each seed create one RNG based on SeedSequence([MASTER_SEED, seed]) and pass that same mutable RNG object successively to both algorithms. Forward order is generational then steady-state; reverse order is steady-state then generational. Recreate all RNGs from their SeedSequences for each mode/order experiment.
10. Produce four CSV files: independent_forward.csv, independent_reverse.csv, shared_forward.csv, and shared_reverse.csv. Each must have exactly 30 data rows sorted by seed regardless of execution order. Use UTF-8, comma delimiters, a single header, Unix newline '\n', no index, no comments, no timestamps, and no platform-dependent metadata.
11. Use this exact column order: seed, then for the generational prefix and then the steady_state prefix: initialization_target, initialization_accepted, initialization_attempts, initialization_misses, initialization_failed, offspring_target, offspring_accepted, offspring_attempts, offspring_misses, offspring_failed, best_score, duplicate_ratio. Thus, for example, generational_initialization_target precedes generational_initialization_accepted, and all 12 generational fields precede all 12 steady_state fields. Serialize counters and scores as base-10 integers, failure indicators as 0 or 1, and duplicate_ratio with exactly 12 digits after the decimal point using format(value,'.12f').
12. Compare independent_forward.csv with independent_reverse.csv both as complete byte arrays using SHA-256 and line-by-line after the common header. Record the number of byte-identical per-seed lines; the required independent result is 30 of 30 and equal whole-file SHA-256 digests.
13. For each mode, compare forward versus reverse using these eight audit columns: generational_initialization_attempts, steady_state_initialization_attempts, generational_offspring_attempts, steady_state_offspring_attempts, generational_duplicate_ratio, steady_state_duplicate_ratio, generational_best_score, and steady_state_best_score. For each column, compute the fraction of the 30 seeds whose serialized field differs. Also compute the union row-change rate: the fraction of seeds differing in at least one of the eight columns.
14. Declare the hypothesis supported if and only if independent mode has 30/30 byte-identical lines and equal whole-file hashes, and the maximum shared-mode column-specific row-change rate is at least 0.80, meaning at least 24 of 30 seeds differ in at least one single audit column. Declare it refuted otherwise. The union row-change rate is descriptive and does not replace the column-specific 0.80 criterion.
15. Save audit_metrics.json containing both SHA-256 hashes for each comparison, independent identical-line count, all eight column-specific change counts and rates for each mode, each mode's union change count and rate, and the supported/refuted decision.
16. Create order_reversal_heatmap.png with two vertically stacked 30-by-8 binary heatmaps, independent mode above shared mode. Rows are seeds 0-29; columns are the eight audit columns in the order listed in step 13; a cell is 1 if forward and reverse serialized values differ and 0 otherwise. Use a fixed white-to-dark-red color scale with vmin=0 and vmax=1, label both axes, include a colorbar labeled 'order-induced change', use tight_layout(), and save at 160 DPI.

## Metrics
- Independent byte-identical row count: number of seeds whose complete canonical CSV line is identical between independent_forward.csv and independent_reverse.csv; required value is 30/30.
- Independent whole-file equality: equality of SHA-256 digests for the two independent-mode CSV byte arrays; required value is true.
- Column-specific order-change rate: for each of the eight audit columns, number of seeds with unequal serialized forward/reverse values divided by 30, computed separately for independent and shared modes.
- Shared maximum column-change rate: maximum of the eight shared-mode column-specific rates; the hypothesis requires at least 0.80, equivalently at least 24 changed seeds in one column.
- Union row-change rate: fraction of seeds that differ in at least one of the eight audit columns, reported separately for independent and shared modes as a descriptive robustness measure.
- Failure counts: sums of initialization_failed and offspring_failed over the 30 seeds for each algorithm, mode, and order, included to expose capped or incomplete runs.

## Time budget
20 minutes (ceiling 30).

## Expected outcomes
- **If supported:** The independent forward and reverse files have equal SHA-256 digests and all 30 per-seed lines are byte-identical; every independent audit-column change rate is 0.00. In shared mode, at least one audit column, expected to be an offspring_attempts or duplicate_ratio column, differs for at least 24 of 30 seeds, so its change rate is at least 0.80; the shared heatmap consequently contains a dense changed column while the independent heatmap is entirely zero.
- **If refuted:** The hypothesis is refuted if even one independent per-seed line differs or the independent file hashes differ, or if every shared-mode audit column changes for at most 23 of 30 seeds, giving a maximum column-specific change rate below 0.80.
