# Literature survey: Can a raw per-seed file be released containing initialization attempts and misses, offspring attempts and misses, target counters, failure indicators, both scores, and per-run duplicate ratios for both algorithms?

Genetic-algorithm performance is commonly evaluated across repeated stochastic runs rather than from a single aggregate outcome. Jenkins et al. compare four GA variants over 30 runs and use the number of function evaluations as a central measure of computational effort [1]. Their methodology also shows why event-level accounting matters: generational, steady-state, steady-generational, and \((\mu+\mu)\) algorithms create and replace offspring differently, so a nominal iteration or generation is not directly comparable across variants. Function-evaluation counts provide a more consistent basis, but they do not reveal where effort was spent or lost. For an experiment involving two algorithms, per-seed initialization attempts, offspring attempts, and corresponding misses would therefore expose operational differences that aggregate scores or iteration counts could conceal.

The proposed duplicate-ratio fields are especially relevant to established concerns about diversity loss and premature convergence. Boulesnane identifies population initialization, stagnation, diversity loss, and premature convergence as recurring difficulties in evolutionary computation, while emphasizing that iterative searches generate valuable data about population dynamics [3]. Li goes further by using gene repetition rates as feedback for adapting crossover and mutation probabilities, reporting improved diversity and search behavior relative to a traditional GA on flexible job-shop scheduling benchmarks [2]. Although gene repetition is not necessarily identical to a duplicate-individual ratio, both measure redundancy in the evolving population. Releasing a clearly defined per-run duplicate ratio for each algorithm would permit analysis of whether failures, misses, or score differences coincide with reduced diversity. The file should state whether duplication is measured among all generated candidates, accepted offspring, or the population at a specified point, because these denominators represent different phenomena.

Initialization records are also pertinent to reproducibility. Ahn et al. formalize reproducibility under noisy operations and inexact initialization, showing that reproducibility can trade off against computation in optimization settings [9]. Zhang et al. likewise study output deviations under small changes to training and explicitly treat inexact initialization, although their guarantees concern convex optimization rather than GAs [10]. These works do not prescribe evolutionary-algorithm logging formats, but they support retaining seed-level information instead of publishing only means. Seed-indexed rows would allow the two algorithms to be compared under matched stochastic conditions, provided that seed handling and random-number-stream allocation are documented. Failure indicators and target counters are important complements: a missing score should be distinguishable from a valid poor score, and a target counter should specify both the target definition and whether it records attempts, evaluations, or successful hits.

The retrieved literature does not establish a standard schema containing all requested fields. Nevertheless, it supports separating search effort, diversity, success, and final performance rather than compressing them into one result. A useful raw file would include identifiers for seed and algorithm; initialization and offspring attempts and misses; target counters; explicit failure codes; both scores with unambiguous names, directions, and missing-value rules; and duplicate counts plus denominators from which ratios can be verified. Algorithm parameters and stopping conditions should accompany the file because crossover, replacement, and evaluation policies materially affect what an “attempt” or “run” means [1].

## Gap

The specific untested question is whether releasing this complete, matched per-seed record changes the interpretation of the two algorithms’ aggregate comparison. None of the retrieved sources jointly analyzes initialization misses, offspring misses, target attainment, failures, two score measures, and duplicate ratios at run level. A new experiment should therefore test whether score differences persist after separating successful from failed runs and whether attempt inefficiency or duplication explains observed failures. The raw release is feasible in principle, but its scientific value depends on precise field definitions, reproducible seed handling, explicit denominators, and retention of failed runs rather than silently dropping them.
