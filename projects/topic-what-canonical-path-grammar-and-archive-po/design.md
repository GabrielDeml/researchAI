# Experiment design: Topic What canonical path grammar and archive policy should be used to reject duplicate names, traversal, absolute paths, Unicode normalization collisions, case-folding collisions, platform-specific aliases, and ambiguous parser behavior? _(auto-enqueued follow-up from topic-can-the-complete-repository-and-release-pa)_

**Hypothesis:** A component trie that rejects canonical-path prefix conflicts will reject all 72 archives containing a regular file or symbolic link at canonical path p together with an entry below p, a file-directory type conflict at p, or two differently spelled implicit directories mapping to p, regardless of entry order; an exact-key-only duplicate detector will accept at least 48 of these archives, while both validators will accept all 24 nonconflicting controls.

## Summary
Generate 72 adversarial and 24 control PAX archives, then compare an archive-wide canonical component-trie validator with an exact-canonical-key duplicate detector under both entry orders.

## Protocol
1. Use Python 3.11 or later with only the standard library plus matplotlib. Set `random.seed(20250308)`, although corpus generation must otherwise be fully enumerated and nonrandom. Do not extract any archive to the filesystem.
2. Represent archive entries as `(raw_name, type)`, where `type` is exactly one of `regular`, `directory`, or `symlink`. Regular files contain one byte `b'x'`; directories contain no data; symbolic links have inert target `safe-target`, which neither validator resolves.
3. Implement one shared path parser used by both validators. Convert backslashes to `/`. Reject a name if it is empty; begins with `/` before or after separator conversion; matches an ASCII drive prefix `^[A-Za-z]:`; contains a colon anywhere; contains NUL, a C0 control character U+0001 through U+001F, or DEL U+007F; or contains an empty component, including from repeated or trailing separators. For every component, compute `unicodedata.normalize('NFKC', component).casefold().rstrip(' .')`; reject if the result is empty, `.` or `..`, or if its substring before the first `.` is one of `con`, `prn`, `aux`, `nul`, `com1` through `com9`, or `lpt1` through `lpt9`. The canonical path is the transformed components joined by `/`. Preserve, separately, the tuple of original Unicode components after only converting backslashes to `/`; call this the raw-component tuple.
4. Before the main experiment, test the parser against a fixed oracle. Valid input-to-canonical-output pairs are: `a/b` to `a/b`; `A/B` to `a/b`; `a\\b` to `a/b`; `café/x` to `café/x`; `cafe` followed by U+0301 then `/x` to `café/x`; `Ａlpha/x` to `alpha/x`; `Data./x` to `data/x`; `Data ` followed by `/x` to `data/x`; `Straße/x` to `strasse/x`; and `x/y-z_1` to `x/y-z_1`. Inputs that must be rejected are: empty string, `/abs`, `\\abs`, `C:/abs`, `c:\\abs`, `\\\\server\\share\\x`, `//server/share/x`, `../x`, `a/../x`, `..\\x`, `a\\..\\x`, two fullwidth full stops followed by `/x`, `a/` followed by two fullwidth full stops then `/x`, `a//b`, `a\\\\b`, `a/ /b`, `.`, `a/.`, `a:b`, `file:stream`, `a` plus `chr(0)` plus `b`, `a` plus `chr(10)` plus `b`, `a` plus `chr(127)` plus `b`, `CON`, `nul.txt`, `a/COM1`, and `Lpt9/data`. Require exact agreement with all oracle outcomes.
5. Implement the baseline validator, named `exact-key`. Parse every entry and reject the entire archive on any parser error. Otherwise reject if any two entries have the same complete canonical path, regardless of entry type. Ignore prefix relationships, descendants, and raw-component spelling. Accept otherwise.
6. Implement the comparison validator, named `component-trie`, as an archive-wide, order-independent analysis. Parse all entries first. Build a trie keyed by canonical components. At each complete canonical path, record all explicit entry types. At every trie node used as a proper directory prefix of an entry, record the corresponding prefix of that entry's raw-component tuple. Reject if any complete canonical path occurs more than once; if a node has both a directory and a regular-file or symlink entry; if a node containing an explicit regular file or symlink has any proper descendant; or if any node used as a proper prefix has more than one distinct raw-prefix tuple. Accept otherwise. Compute these predicates after collecting all entries rather than making an irreversible first-entry-wins decision.
7. Generate 24 ancestor-conflict archives. For index `i` from 0 through 23, set `p = f'ancestor{i:02d}/node'`. Add an entry at `p`, using type `regular` for `i < 12` and `symlink` otherwise, plus a regular entry at `p + '/child.txt'`. Each archive has exactly these two entries.
8. Generate 24 file-directory type-conflict archives. For index `i` from 0 through 23, set `p = f'type{i:02d}/node'`. Add a `directory` entry at `p` and a second entry at exactly `p`, using type `regular` for `i < 12` and `symlink` otherwise.
9. Generate 24 implicit-directory spelling-collision archives from the Cartesian product of six alias pairs and four contexts. The alias pairs are `('Alpha','alpha')`, `('café','cafe' + U+0301)`, `('Ａlpha','Alpha')`, `('data.','data')`, `('data ','data')`, and `('Straße','STRASSE')`. The contexts are the empty prefix, `outer`, `outer/deep`, and `x/y/z`. For each pair `(left_alias, right_alias)` and context, form `left_prefix` and `right_prefix` by appending the alias as the next component of the context. Add regular entries `left_prefix + '/left.txt'` and `right_prefix + '/right.txt'`. Their complete canonical paths must differ, while their proper parent canonical paths must be equal and their raw parent tuples must differ.
10. Generate 24 nonconflicting controls. Controls 0 through 7 contain a directory at `ctrl-dir{i}/node` and a regular file at `ctrl-dir{i}/node/child.txt`. Controls 8 through 15 contain regular files at `ctrl-file{i}/node` and `ctrl-file{i}/node2/child.txt`, where `i` runs from 0 through 7; these are component-wise siblings, not prefix conflicts. Controls 16 through 23 contain regular files at `ctrl-implicit{i}/node/left.txt` and `ctrl-implicit{i}/node/right.txt`, using identical raw spelling for their shared implicit directories.
11. Materialize every two-entry manifest as an in-memory tar archive using `tarfile.PAX_FORMAT`, once in listed order and once in reversed order, for a total of 192 tar streams: 144 conflict streams and 48 control streams. Read each stream back with `tarfile`, preserving member order. Before validation, assert that the two decoded member names and types exactly match the source manifest; terminate with a corpus-integrity failure if they do not.
12. Run both validators on all 192 decoded streams. Save one CSV row per validator-stream pair with archive ID, class (`ancestor`, `type`, `implicit_alias`, or `control`), order (`forward` or `reverse`), validator, accepted boolean, and rejection reason. Also save a JSON summary containing all aggregate counts and parser-oracle results.
13. For each validator and class, compute the accepted-run count out of 48 runs for each 24-archive conflict class and out of 48 runs for controls. Also compute archive-level acceptance, where an archive counts as accepted only if both orders are accepted, and order disagreement, where the two orders produce different booleans.
14. Create `acceptance_by_class.png` as a grouped bar chart with classes `ancestor`, `type`, `implicit alias`, and `control` on the x-axis; one bar each for `exact-key` and `component-trie`; and y-axis equal to percentage of the 48 order-specific runs accepted. Fix the y-axis to 0 through 100, label every bar with its integer accepted-run count, and annotate the total order-disagreement count for each validator.
15. Declare the hypothesis supported only if all of the following exact thresholds hold: parser-oracle accuracy is 100%; `component-trie` rejects all 72 conflict archives in both orders, equivalently 0 of 144 conflict runs accepted; `exact-key` accepts at least 48 of the 72 conflict archives in both orders, equivalently at least 96 of 144 conflict runs accepted with no order disagreements; both validators accept all 24 controls in both orders, equivalently 48 of 48 control runs each; and `component-trie` has zero order disagreements. Any failed condition refutes the hypothesis.

## Metrics
- Parser-oracle accuracy: number of valid and invalid path cases matching their specified canonicalization or rejection outcome divided by the total oracle cases; support threshold is 100%.
- Component-trie conflict rejection rate: conflict runs rejected divided by 144; support threshold is 144/144, with all 72 archive IDs rejected in both orders.
- Exact-key conflict acceptance count: conflict archive IDs accepted in both orders; support threshold is at least 48/72, with the predicted count exactly 48/72.
- Per-class run acceptance: accepted runs out of 48 separately for ancestor, type, implicit-alias, and control classes for each validator.
- Control acceptance rate: control runs accepted divided by 48 for each validator; support threshold is 48/48 for both.
- Order-disagreement count: number of archive IDs for which forward and reverse orders yield different decisions; support threshold is zero for component-trie and, for the stated baseline result, zero for exact-key.
- Corpus-integrity rate: reconstructed tar member name-and-type sequences exactly matching generated manifests; required threshold is 192/192.

## Expected outcomes
- **If supported:** Parser and corpus-integrity checks are perfect. Component-trie acceptance is 0/48 for each of the ancestor, type, and implicit-alias run groups and 48/48 for controls, with zero order disagreements. Exact-key acceptance is 48/48 for ancestor, 0/48 for type, 48/48 for implicit alias, and 48/48 for controls, corresponding to exactly 48 of 72 conflict archives accepted in both orders and 96 of 144 conflict runs accepted.
- **If refuted:** The hypothesis is refuted if component-trie accepts even one conflict archive in either order, exact-key accepts fewer than 48 conflict archives in both orders, either validator rejects any control in either order, component-trie has any order-dependent decision, or the mandatory parser-oracle or corpus-integrity check is not 100%.
