# Peer review

**Score:** 4.5/10  _(after one revision pass)_

## Strengths
- The claims are unusually well calibrated: the report explicitly limits its conclusion to deterministic, positive-path testing of well-formed loose SHA-1 objects and does not present 12/12 as a statistical success rate.
- The threat boundary is clearly stated. The distinction between literal object access, revision interpretation, replacement-aware traversal, and checkout state is technically meaningful and generally sound.
- The replacement-enabled and GIT_NO_REPLACE_OBJECTS controls are appropriate baselines and support the narrow conclusion that replacement processing explains the observed Git traversal divergence.
- The mutation suite covers several semantically important inventory dimensions, including paths, blob identities, executable modes, symlinks, gitlinks, subtree changes, pointer-shaped blobs, and combined mutations.
- The report correctly avoids claiming effective LFS classification, LFS payload authentication, publisher authentication, parser hardening, performance, or production readiness.
- The methodology describes deterministic environment controls, argument-array command invocation, explicit SHA-1 repository initialization, and construction of objects independently of the working tree.
- The limitations section is comprehensive and candid, identifying circular oracle construction, absent adversarial testing, storage-format limitations, race conditions, resource exhaustion, SHA-1 concerns, and missing artifacts.
- The prose is clear and technically careful. The main result follows from the described design and is consistent with documented Git behavior.

## Weaknesses
- The central empirical result is not independently reproducible or auditable because the verifier source, fixture generator, manifests, command transcript, raw outputs, expected inventories, count derivation, artifact hashes, and referenced figure are absent.
- The expected original inventories were generated by the same raw-object implementation under test. This creates substantial oracle circularity: shared parsing, mode classification, path handling, pointer extraction, or canonicalization defects could pass unnoticed.
- Although the no-replacement Git control provides useful corroboration, the report does not preserve enough per-field evidence to show that Git and the raw reader agreed independently on every path, mode, kind, object ID, and pointer field.
- The experiment mostly demonstrates a direct consequence of the implementation boundary: code that opens a loose object by pathname and never reads refs will not honor refs/replace. This is expected from Git's documented semantics, so the empirical novelty is limited.
- Only positive-path, Git-generated objects were tested. The security-relevant parser and fail-closed claims are largely untested, including malformed headers, malformed commits and trees, unsupported modes, duplicate entries, truncation, trailing data, pathological zlib input, depth limits, and size limits.
- The implementation handles only loose SHA-1 objects. Real repositories commonly use packfiles and may use alternates, multi-pack indexes, promisor storage, or SHA-256, making the prototype too restricted to substantiate a general repository-verifier design.
- The checkout-state divergence setup is not a meaningful test of checkout-state isolation because neither decisive implementation consumes checkout state. It verifies fixture separation but does not detect accidental index or worktree use in plausible competing verifier implementations.
- The report gives only aggregate 12/12 outcomes rather than per-case inventories or structured diffs. Consequently, readers cannot inspect whether each fixture actually exercised the claimed semantic distinction.
- The reported 635 object validations and zero failures are unsupported aggregate numbers without source, logs, or a derivation. Their inclusion adds little evidentiary value.
- The scope of replacement testing is narrow: only root commits are replaced, while replacements of trees or blobs, tag handling, parent traversal, merge commits, and history-level behavior are not exercised.
- The raw object access design raises unresolved repository-boundary and filesystem-security questions, such as symlink-safe opening, repository discovery, object-path substitution, alternates policy, atomicity, and concurrent mutation.
- The manuscript is longer and more repetitive than warranted by the modest result; limitations and caveats recur across the abstract, background, method, results, and limitations sections.

## Required fixes
- Provide a complete, immutable reproducibility artifact containing the exact verifier and fixture-generator source, declarative fixture manifests, command transcript, captured environment and Git configuration, raw stdout and stderr, exit statuses, per-case outputs, canonical inventories, count derivations, figure source, and cryptographic hashes.
- Replace the circular expected-value construction with an independent oracle. Generate expected records directly from declarative manifests, then compare them field by field with both a pre-replacement Git traversal and a post-installation traversal using GIT_NO_REPLACE_OBJECTS=1.
- Report per-fixture structured results, including original and replacement commit and tree IDs, expected inventory differences, raw-verifier output, replacement-aware Git output, no-replacement Git output, and explicit assertions for the property targeted by each mutation.
- Add adversarial negative tests for malformed loose-object headers, incorrect sizes, invalid object types, malformed commit headers, absent or duplicate tree headers, truncated tree entries, invalid delimiters, unsupported modes, duplicate names, invalid ordering, missing referenced objects, trailing compressed data, and corrupted hashes.
- Define and test explicit resource limits for compressed size, decompressed size, object count, cumulative bytes, path length, tree depth, CPU time, and compression ratio, including decompression-bomb and deeply nested-tree fixtures.
- Either implement and test safe packfile and index support, alternates policy, multi-pack indexes, promisor-object behavior, and SHA-256 repositories, or retitle and frame the work strictly as a loose-object SHA-1 proof of concept rather than a repository verifier.
- Add realistic negative controls for checkout-state confusion: implement deliberately unsafe variants that inventory the index, worktree, sparse projection, or replacement-aware Git output, and show that the test suite detects each error while the proposed verifier excludes those inputs.
- Test replacement of commits, trees, and blobs separately, and expand coverage to parented and merge commits. If tags are within scope, specify literal tag handling and test annotated-tag peeling without revision interpretation.
- Specify a race-resistant object-access model and test concurrent mutation scenarios, including deletion, substitution, repacking, and repository metadata changes, demonstrating either a consistent authenticated snapshot or deterministic failure.
- Remove or fully substantiate the 635-validation and zero-failure counts, include the missing figure artifact, and streamline repeated caveats so that the manuscript emphasizes the actual contribution: a narrowly scoped verifier contract and test design rather than discovery of replacement-ref behavior.
