# Experiment design: Topic Can the verifier be implemented against actual Git repositories, deriving tracked paths, blob identities, tree modes, symlinks, executable bits, submodules, and Git LFS semantics from an authenticated commit or tag? _(auto-enqueued follow-up from topic-can-the-complete-repository-and-release-pa)_

**Hypothesis:** For twelve repositories in which an authenticated commit object is assigned a replacement commit through `refs/replace` and the index, working tree, and sparse-checkout configuration describe different states, a raw-object verifier pinned to the authenticated object ID will return the original commit's tree inventory in all twelve cases, while ordinary replacement-aware Git traversal will return the adversarial replacement inventory in all twelve.

## Summary
Create twelve deterministic synthetic Git repositories with pinned original commits, adversarial commit replacements, and divergent sparse-checkout/index/working-tree states, then compare a replacement-disabled raw-object verifier with ordinary replacement-aware Git traversal.

## Protocol
1. Preflight: use Python 3.10 or newer, Git 2.25 or newer, and matplotlib 3.8.4; fail the experiment if `git --version` is unavailable or SHA-1 repositories are unsupported. Set `LC_ALL=C`, `TZ=UTC`, `PYTHONHASHSEED=0`, and Python's random seed to 20250308. Create a fresh output directory containing `repos/`, `results/`, and `results/key_result.png`. Disable all inherited Git configuration for every subprocess by setting `GIT_CONFIG_NOSYSTEM=1`, `HOME` to a fresh empty directory, and `GIT_TERMINAL_PROMPT=0`.
2. Implement helpers that invoke Git with argument arrays, never a shell. Initialize twelve repositories named `case-00` through `case-11` using `git init --object-format=sha1`, then set `gc.auto=0`, `user.name=Verifier Experiment`, and `user.email=verifier@example.invalid`. Set commit environment variables to `GIT_AUTHOR_NAME=Verifier Experiment`, `GIT_AUTHOR_EMAIL=verifier@example.invalid`, `GIT_COMMITTER_NAME=Verifier Experiment`, `GIT_COMMITTER_EMAIL=verifier@example.invalid`, and, for case k, author and committer date `1700000000 + k +0000`.
3. Build all blobs, trees, and commits with `git hash-object -w --stdin`, `git mktree --missing`, and `git commit-tree`; do not use the working tree to construct commits. Each original tree must contain these leaf entries: `README.md` mode 100644; `visible/case.txt` mode 100644; `bin/run.sh` mode 100755; `links/readme-link` mode 120000 with blob bytes `../README.md`; `vendor/dependency` mode 160000 whose gitlink object ID is the fixed 40-hex value `1111111111111111111111111111111111111111`; `.gitattributes` mode 100644 with bytes `assets/model.bin filter=lfs diff=lfs merge=lfs -text\n`; `assets/model.bin` mode 100644 containing the valid LFS pointer `version https://git-lfs.github.com/spec/v1\noid sha256:aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa\nsize 12345\n`; and `nested/data.txt` mode 100644. Include the case number in the contents of `README.md`, `visible/case.txt`, and `nested/data.txt` so the twelve original commits are distinct. Create a root commit with message `original case-K\n`, no parent, and update `refs/heads/main` to it. Record its SHA-1 as O_k.
4. Create one replacement commit R_k per repository by copying the original inventory and applying exactly one mutation: case 00 replaces the `README.md` blob contents; case 01 renames `nested/data.txt` to `nested/renamed.txt`; case 02 changes `bin/run.sh` from mode 100755 to 100644; case 03 changes the `links/readme-link` symlink target blob to `../nested/data.txt`; case 04 changes `links/readme-link` from mode 120000 to a mode-100644 regular blob; case 05 replaces the executable `bin/run.sh` blob while retaining mode 100755; case 06 changes the `vendor/dependency` gitlink ID to `2222222222222222222222222222222222222222`; case 07 changes the LFS pointer OID to 64 lowercase `b` characters and size to 54321; case 08 changes `.gitattributes` to `assets/model.bin -filter -diff -merge text\n`; case 09 deletes the entire `nested` subtree; case 10 adds `adversarial/new.txt` mode 100644; and case 11 simultaneously deletes `README.md`, changes `visible/case.txt`, changes the executable bit of `bin/run.sh`, and changes the gitlink ID to `3333333333333333333333333333333333333333`. Commit each replacement tree with message `replacement case-K\n`, no parent, and timestamp `1700001000 + k +0000`. Record the resulting commit SHA-1 as R_k. Assert O_k differs from R_k.
5. Before installing any replacement ref, authenticate and snapshot O_k. Implement a raw loose-object reader in Python that opens `.git/objects/<first-two-hex>/<remaining-hex>`, zlib-decompresses it, parses `<type> <decimal-size>\0<payload>`, checks the declared size, and recomputes `SHA1(header || payload)` to require equality with the requested object ID. It must not invoke revision parsing, read refs, inspect the index or working tree, or honor alternates. Parse the raw commit payload to obtain its `tree` header. Parse binary tree payloads as repeated `<ASCII mode><space><path bytes><NUL><20-byte object ID>` entries; recurse only into mode 040000 trees and treat modes 100644, 100755, 120000, and 160000 as leaves. For every blob leaf, validate its blob object hash. Do not attempt to open the object named by a 160000 gitlink.
6. Canonicalize every inventory as a sorted list ordered by raw path bytes. Each record must contain path encoded as lowercase hexadecimal bytes, six-digit mode, inferred kind (`blob`, `symlink`, or `gitlink`), and lowercase object ID. For mode-100644 blobs only, additionally parse Git LFS semantics if and only if the complete blob is a valid three-line pointer with the exact version line, an `oid sha256:` line containing 64 lowercase hexadecimal characters, and a decimal `size` line; store the parsed LFS SHA-256 and size, otherwise store null values. Serialize canonical inventories as UTF-8 JSON with sorted keys and compact separators, and fingerprint them with SHA-256.
7. Run the raw reader on O_k before adversarial setup, save the canonical inventory and fingerprint in an external file `authenticated-case-K.json`, and save O_k as the pinned authenticated commit ID. Independently run the same raw reader on R_k and save its canonical replacement inventory. These files are expected-result fixtures only; the tested verifier must later receive only the repository path and pinned O_k, not R_k or branch names.
8. Populate the checkout before replacement installation: run `git checkout -f main`; run `git sparse-checkout init --no-cone`; then pass the sole pattern `/visible/` followed by a newline to `git sparse-checkout set --no-cone --stdin`. Immediately snapshot the sparse projection as the set of stage-0 paths lacking the skip-worktree bit, obtained from `git ls-files -v -z`; require that `visible/case.txt` is projected and at least one original path is skip-worktree.
9. Make the index and working tree disagree without changing HEAD. Write a deterministic blob `index-only case-K\n` using `git hash-object -w --stdin`, then add it only to the index as `visible/index-only.txt` with mode 100644 using `git update-index --add --cacheinfo`. Do not create that file in the working tree. Replace the working-tree contents of `visible/case.txt` with `working-tree mutation case-K\n` without staging it, and create untracked `visible/worktree-only.txt` containing `untracked case-K\n`. Confirm with `git status --porcelain=v1` that `visible/case.txt` is modified, `visible/index-only.txt` is deleted or absent from the working tree relative to the index, and `visible/worktree-only.txt` is untracked.
10. Snapshot the index inventory using `git ls-files --stage -z`, retaining only stage 0 and canonicalizing path, mode, and blob/gitlink ID. Snapshot the physical working-tree inventory by recursively scanning all files below the repository except `.git`: encode symlinks as mode 120000 and hash their link-target bytes as Git blobs; encode regular files as 100755 when any user executable bit is set and otherwise 100644, and hash their bytes as Git blobs; include untracked files; do not infer gitlinks from directories. Save both fingerprints. Require the original, replacement, index, and working-tree fingerprints to be pairwise distinct, and require the sparse projected path set to differ from each of their complete path sets; otherwise mark the case as an invalid fixture.
11. Install the attack only after all checkout-state construction by running `git replace O_k R_k`. Verify that `.git/refs/replace/O_k` resolves to R_k. Do not set `GIT_NO_REPLACE_OBJECTS` for the ordinary traversal.
12. Test the raw verifier by rerunning the Python loose-object verifier with the repository path and literal pinned O_k. Compare its canonical inventory byte-for-byte with the authenticated original snapshot and separately with the replacement snapshot. Also require every raw object hash validation to pass and require the parsed commit's tree ID to equal the original snapshot's tree ID.
13. Test ordinary replacement-aware traversal by running `git ls-tree -r -z --full-tree O_k` with default replacement behavior. Parse each NUL-delimited record as `<mode> <type> <object-id>\t<path>`, canonicalize it using the same representation, and inspect referenced blobs with ordinary `git cat-file blob <object-id>` to attach the same LFS fields. Compare this inventory byte-for-byte with the raw snapshot of R_k and separately with the raw snapshot of O_k. As a replacement-activation control, run the same `git ls-tree` command with `GIT_NO_REPLACE_OBJECTS=1` and require that it equals the original inventory.
14. Write `results/cases.json` with one record per case containing O_k, R_k, all inventory fingerprints, fixture-validity flags, raw-versus-original equality, raw-versus-replacement equality, ordinary-versus-original equality, ordinary-versus-replacement equality, no-replace-control-versus-original equality, and elapsed seconds. Write an aggregate `results/summary.json` containing all metrics and the final decision.
15. Produce `results/key_result.png` with matplotlib at 160 DPI. Draw four fixed-order bars on a 0-to-12 y-axis: `Raw = original`, `Raw = replacement`, `Ordinary = original`, and `Ordinary = replacement`; bar heights are the corresponding case counts. Print each integer count above its bar, label the y-axis `Repositories (n=12)`, and title the figure `Effect of refs/replace on traversal pinned to the same commit ID`.
16. Declare the hypothesis supported only if all 12 fixtures are valid, raw traversal equals the original and not the replacement in 12/12 cases, ordinary traversal equals the replacement and not the original in 12/12 cases, the `GIT_NO_REPLACE_OBJECTS=1` control equals the original in 12/12 cases, and there are zero object-hash, parsing, or command failures. Declare it refuted if any valid case has raw traversal differing from the authenticated original or ordinary replacement-aware traversal differing from the adversarial replacement. Treat setup failures, unsupported Git versions, or invalid fixtures as experiment errors rather than evidence. Ensure total execution is terminated as an error if it exceeds 30 minutes.

## Metrics
- raw_original_match_count: number of the 12 repositories whose raw loose-object inventory for pinned O_k is byte-for-byte equal to the authenticated original inventory; support requires 12
- raw_replacement_match_count: number whose raw inventory for O_k equals the R_k inventory; support requires 0
- ordinary_replacement_match_count: number whose default `git ls-tree` inventory for literal O_k equals the raw R_k inventory; support requires 12
- ordinary_original_match_count: number whose default replacement-aware inventory equals the original inventory; support requires 0
- no_replace_control_match_count: number whose `GIT_NO_REPLACE_OBJECTS=1 git ls-tree` inventory for O_k equals the original inventory; support requires 12
- fixture_divergence_count: number with pairwise-distinct original, replacement, index, and physical working-tree fingerprints plus a distinct nonempty sparse projection; support requires 12
- object_integrity_failure_count: count of commit, tree, or blob objects with a size mismatch or recomputed Git SHA-1 different from the requested ID; support requires 0
- case_runtime_seconds and total_runtime_seconds: monotonic elapsed time per case and overall; total must be at most 1800 seconds

## Time budget
30 minutes (ceiling 30).

## Expected outcomes
- **If supported:** All 12 fixtures are valid; the four figure bars are exactly 12, 0, 0, and 12 for `Raw = original`, `Raw = replacement`, `Ordinary = original`, and `Ordinary = replacement`, respectively; the replacement-disabled control is 12/12 original matches and object-integrity failures are zero.
- **If refuted:** At least one valid repository yields a raw inventory for pinned O_k that is not the authenticated original, or at least one default replacement-aware traversal fails to equal R_k; equivalently, raw_original_match_count or ordinary_replacement_match_count is below 12, or either forbidden cross-match count is above 0.
