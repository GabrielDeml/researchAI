# Experiment design: Topic Can the original executable source code, exact dependency versions, environment specification, and timestamped machine-readable outputs be archived under a persistent identifier? _(auto-enqueued follow-up from genetic-algorithms-2)_

**Hypothesis:** For 50 pairs of semantically identical RO-Crate metadata documents generated with randomized JSON key order, whitespace, and entity order, hashing raw ZIP bytes will assign different identifiers to at least 90% of pairs, whereas hashing a bundle representation using canonical JSON, normalized archive paths, fixed file permissions, and fixed ZIP timestamps will assign the same identifier to all 50 pairs.

## Summary
Generate 50 pairs of semantically identical synthetic RO-Crates with deliberately different JSON serializations, then compare SHA-256 identifiers computed from raw ZIP bytes against identifiers computed from a fully specified canonical ZIP representation.

## Protocol
1. Use CPython 3.11 or newer and create a single implementation script named `experiment.py`. The only third-party package may be `matplotlib==3.9.2`, used solely to create the PNG figure; all archive, JSON, hashing, randomization, and CSV operations must use the Python standard library. Set the master random seed to 20250308 and do not use current time, filesystem metadata, locale-dependent formatting, or nondeterministic iteration over sets.
2. Create output directories `artifacts/raw`, `artifacts/canonical`, and `results`. Generate exactly 50 synthetic crate pairs indexed 0 through 49. Each pair represents one semantic research bundle, while different pair indices represent different bundles.
3. For each pair index i, create the same non-metadata files for variants A and B: (a) `src/run.py`, an ASCII executable Python script that reads `data/input.json`, computes the sum of squares of its `values` array, and writes JSON containing `pair_index`, `sum_squares`, and the fixed timestamp `2025-01-01T00:00:00Z`; (b) `data/input.json`, encoded as compact sorted-key JSON plus a final newline, containing `pair_index: i` and `values: [i, i+1, i+2]`; (c) `outputs/results.json`, encoded as compact sorted-key JSON plus a final newline, containing `pair_index: i`, `sum_squares: i*i + (i+1)*(i+1) + (i+2)*(i+2)`, and `generated_at: "2025-01-01T00:00:00Z"`; (d) `requirements-lock.txt` with the exact bytes `# No third-party runtime dependencies; Python standard library only\n`; and (e) `environment.json`, encoded as compact sorted-key JSON plus a final newline, containing `python: "3.12.8"`, `implementation: "CPython"`, `os: "any"`, and `architecture: "any"`. Use identical bytes for these five files in A and B.
4. Construct one RO-Crate JSON-LD metadata object per pair. It must have `@context` equal to `https://w3id.org/ro/crate/1.1/context` and an `@graph` containing entities for `ro-crate-metadata.json`, the root dataset `./`, and each of the five files. Give every entity a unique `@id`; give the metadata descriptor `@type: "CreativeWork"` and `about: {"@id":"./"}`; give the root `@type: "Dataset"`, name `Synthetic reproducibility bundle i`, datePublished `2025-01-01T00:00:00Z`, and a `hasPart` array of single-key `{"@id": path}` references to all five files; give each file entity `@type: "File"`, its byte length, and its lowercase hexadecimal SHA-256 checksum under the key `sha256`. Do not include floating-point numbers, blank nodes, `@list`, or arrays other than `@graph` and arrays consisting exclusively of single-key `{"@id": ...}` references.
5. Produce metadata serializations A and B using independent RNG instances seeded with `20250308 + 2*i` and `20250308 + 2*i + 1`. Recursively rebuild every JSON object with its keys shuffled by the corresponding RNG. Independently shuffle `@graph` and every array consisting exclusively of `{"@id": ...}` references. If the two resulting `@graph` orders happen to be identical, rotate B's `@graph` by one position. Randomly assign one variant to compact JSON using separators `(',', ':')` with no final newline and the other to pretty JSON with an RNG-selected indentation of either 2 or 4 spaces and one final newline. Encode both as UTF-8 with `ensure_ascii=False` and `allow_nan=False`. Thus each pair is guaranteed to differ in whitespace and entity order while retaining the same parsed JSON-LD content.
6. Validate semantic identity before creating archives. Parse both metadata byte strings. Normalize each parsed document by recursively sorting object keys, sorting `@graph` by each entity's `@id`, and sorting every array made exclusively of single-key `{"@id": ...}` references by `@id`, while preserving all other arrays. Assert that the normalized A and B structures are exactly equal and that all five non-metadata files are byte-for-byte equal. Abort the experiment if any of the 50 validations fails.
7. Create raw ZIP A and raw ZIP B for every pair using `zipfile.ZipFile` with `ZIP_STORED` and `allowZip64=True`. Add the six paths in identical lexicographic path order. Use normalized forward-slash paths, an empty archive comment, empty per-entry comments and extra fields, `create_system=3`, timestamp `(1980,1,1,0,0,0)`, and Unix mode `0100755` for `src/run.py` and `0100644` for every other entry. The only byte-level difference intentionally introduced between raw A and raw B must be the serialization of `ro-crate-metadata.json`. Save them as `artifacts/raw/pair_XX_A.zip` and `artifacts/raw/pair_XX_B.zip`.
8. Compute each raw identifier as `sha256:` followed by the lowercase hexadecimal SHA-256 digest of the complete ZIP byte sequence, including ZIP headers and directory records. Record whether the two raw identifiers in each pair differ.
9. Define canonical path normalization exactly as follows: replace backslashes with `/`; split on `/`; discard empty components and `.` components; reject the path if it is absolute, contains a `..` component, or normalizes to an empty string; then join the remaining components with `/`. Reject duplicate normalized paths.
10. Canonicalize each raw ZIP independently. Read every member and normalize its path using step 9. For `ro-crate-metadata.json`, parse the JSON, recursively sort object keys, sort `@graph` by entity `@id`, sort every array consisting exclusively of single-key `{"@id": ...}` references by `@id`, and preserve all other array orders. Serialize the result as UTF-8 using `json.dumps(..., sort_keys=True, separators=(',', ':'), ensure_ascii=False, allow_nan=False)` followed by exactly one newline. Leave all other file bytes unchanged.
11. Build a new canonical ZIP in memory by writing normalized paths in lexicographic order with `ZIP_STORED`, `allowZip64=True`, an empty archive comment, empty entry comments and extra fields, `create_system=3`, fixed timestamp `(1980,1,1,0,0,0)`, and fixed Unix mode `0100755` for `src/run.py` and `0100644` for all other entries. Set each `ZipInfo.compress_type` explicitly to `ZIP_STORED`. Do not copy any timestamp, permission, entry order, compression setting, or other ZIP metadata from the raw archive.
12. Compute each canonical identifier as `sha256:` followed by the lowercase hexadecimal SHA-256 digest of the complete canonical ZIP bytes. Save each canonical ZIP under `artifacts/canonical/<64-hex-digest>.zip`; if A and B produce the same path, verify that the bytes are identical and retain one deduplicated file. Record whether the two canonical identifiers in each pair are equal.
13. Write `results/pair_metrics.csv` with one row per pair and columns `pair_index`, `semantic_validation_passed`, `raw_id_A`, `raw_id_B`, `raw_ids_different`, `canonical_id_A`, `canonical_id_B`, `canonical_ids_equal`, `raw_size_A`, `raw_size_B`, `canonical_size_A`, and `canonical_size_B`. Write the same information plus aggregate metrics and the fixed experiment timestamp `2025-01-01T00:00:00Z` to `results/summary.json` using sorted keys and indentation of 2 spaces.
14. Calculate the raw fragmentation rate as the number of pairs with different raw identifiers divided by 50, and the canonical preservation rate as the number of pairs with equal canonical identifiers divided by 50. Also count unique raw identifiers among all 100 raw archives and unique canonical identifiers among all 100 canonicalized variants.
15. Create `results/hash_identity_result.png` using matplotlib with two bars on a 0-100% y-axis: `Raw ZIP pairs fragmented` equal to 100 times the raw fragmentation rate and `Canonical pairs preserved` equal to 100 times the canonical preservation rate. Annotate each bar with its integer count out of 50, draw a dashed horizontal line at 90% labeled `raw fragmentation threshold`, and place the canonical requirement `50/50 required` in the canonical bar label or annotation. Use a fixed figure size of 8 by 5 inches, 150 DPI, and `tight_layout()` before saving.
16. Mark the hypothesis `supported` if and only if all 50 semantic validations pass, at least 45 of 50 raw pairs have different identifiers, and exactly 50 of 50 canonical pairs have equal identifiers. Mark it `refuted` otherwise. Store this decision and the three component pass/fail conditions in `results/summary.json`.

## Metrics
- Raw fragmentation count and rate: count pairs for which SHA-256(raw ZIP A) differs from SHA-256(raw ZIP B), then divide by 50; the required threshold is at least 45/50, or 0.90.
- Canonical preservation count and rate: count pairs for which SHA-256(canonical ZIP A) equals SHA-256(canonical ZIP B), then divide by 50; the required threshold is exactly 50/50, or 1.00.
- Semantic validation rate: number of pairs whose normalized parsed metadata structures are equal and whose non-metadata files are byte-identical, divided by 50; it must equal 1.00.
- Identifier multiplicity: count distinct raw identifiers among the 100 raw archives and distinct canonical identifiers among the 100 canonicalized variants; the anticipated values are 100 raw identifiers and 50 canonical identifiers.
- Archive sizes: record raw and canonical byte lengths for both variants of every pair to document serialization overhead and verify that canonical variants within each pair have identical sizes.

## Time budget
10 minutes (ceiling 30).

## Expected outcomes
- **If supported:** All 50 semantic validations pass; at least 45 of 50 raw pairs, and expectedly all 50, have different raw SHA-256 identifiers; exactly 50 of 50 pairs have identical canonical SHA-256 identifiers; and canonicalization reduces the 100 variant archives to exactly 50 pair-specific identifiers.
- **If refuted:** The hypothesis is refuted if any semantic-equivalence validation fails, fewer than 45 of 50 raw pairs receive different raw identifiers, or even one of the 50 semantically identical pairs receives different canonical identifiers.
