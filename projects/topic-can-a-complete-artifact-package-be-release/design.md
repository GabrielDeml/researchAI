# Experiment design: Topic Can a complete artifact package be released containing executable source code, the four CSV files, the heatmap source matrix, a schema-versioned manifest, an environment lock file, and a documented one-command reproduction procedure? _(auto-enqueued follow-up from topic-can-a-raw-per-seed-file-be-released-contai)_

**Hypothesis:** Among 40 coordinated output mutations whose altered files have valid formats and freshly recomputed manifest checksums, relational validation rules linking seed identifiers, row counts, summary values, and heatmap cells across the four CSV files and matrix will detect at least 36 mutations, while all 20 unmodified regenerated output sets will pass.

## Summary
Build a deterministic synthetic artifact package, apply 40 format-valid checksum-refreshed cross-file mutations, and compare checksum-only validation with manifest-declared relational validation while verifying that 20 clean regenerations pass.

## Protocol
1. Create a repository containing `src/generate.py`, `src/validate.py`, `src/mutate.py`, `src/run_experiment.py`, `manifest.schema.json`, `requirements.lock`, `Makefile`, and `README.md`. Pin `numpy==2.1.3` and `matplotlib==3.9.2` in `requirements.lock`; use Python 3.11 or newer and Matplotlib's noninteractive `Agg` backend. The README must document `make reproduce` as the sole reproduction command. The Make target must create `.venv` if absent, install `requirements.lock`, and execute `python -m src.run_experiment --output results`. No runtime network access is permitted except package installation.
2. Define one output set as exactly four CSV files plus one matrix: `observations.csv`, `per_seed.csv`, `summary.csv`, `heatmap_cells.csv`, and `heatmap_matrix.npy`. Every output set must also contain `manifest.json`. Copy one clean set to `release_output/` so the released package directly contains these outputs in addition to executable source, the lock file, schema, and reproduction instructions.
3. Generate deterministic synthetic data for run identifier r. Use 20 seed identifiers `S000` through `S019`, each with 50 observations. For seed index i, instantiate `numpy.random.default_rng(1000000 + 1000*r + i)` and draw 50 values from `Normal(loc=i/10, scale=1+0.02*i)`. Round each generated value to 12 decimal places before any calculation or serialization. Give observations within each seed identifiers `O000` through `O049`.
4. Write `observations.csv` with columns `seed_id,observation_id,value`, sorted by `seed_id` and then `observation_id`, for exactly 1000 data rows. Compute all aggregates from the persisted 12-decimal observation values. For each seed, compute `n`, arithmetic mean using `math.fsum(values)/n`, and sample standard deviation using `sqrt(math.fsum((x-mean)**2 for x in values)/(n-1))`. Write `per_seed.csv` with columns `seed_id,n,mean,sample_std`, one row per seed in lexicographic order, formatting floating-point fields to 12 decimal places.
5. Write `summary.csv` as one data row with columns `seed_count,total_observations,grand_mean`; set these to 20, 1000, and `math.fsum(all_values)/1000`, respectively, with `grand_mean` formatted to 12 decimal places.
6. Write `heatmap_cells.csv` with columns `row_index,seed_id,metric,value`. For each lexicographically ordered seed, emit three rows in metric order `n,mean,sample_std`; `row_index` is the zero-based seed index, and values are copied from the persisted `per_seed.csv` fields. Write `heatmap_matrix.npy` as a float64 array of shape `(20,3)` with the same row order and column order `[n,mean,sample_std]` and values copied from `per_seed.csv`.
7. Define `manifest.schema.json` as a JSON Schema requiring `schema_version`, `generator`, `files`, and `relational_rules`. Each `files` entry must contain relative path, SHA-256, byte size, format, declared columns or NumPy dtype and shape, and data-row count where applicable. Set `manifest.json`'s `schema_version` to `1.0.0`, generator to `synthetic-cross-file-validation-v1`, and list rule identifiers `R1` through `R8` described below. Generate all manifest metadata and SHA-256 hashes only after an output set is complete. The manifest must not hash itself.
8. Implement relational validator rules exactly as follows, using absolute tolerance `5e-10` for floating-point comparisons and exact equality for identifiers and integer counts: R1, `observations.csv` keys `(seed_id,observation_id)` are unique and every seed has a nonempty group; R2, the seed set in `per_seed.csv` equals the seed set in `observations.csv`, and `per_seed.csv` has one row per seed; R3, each `per_seed.n` equals the corresponding observation count; R4, each `per_seed.mean` and `per_seed.sample_std` equals the aggregate recomputed from observations; R5, `summary.seed_count`, `summary.total_observations`, and `summary.grand_mean` equal the seed count, row count, and mean recomputed directly from observations; R6, `heatmap_cells.csv` contains exactly one cell for every Cartesian pair of per-seed row and metric, has the same seed-to-row-index mapping as lexicographically sorted `per_seed.csv`, and has no extra cells; R7, each heatmap cell equals the corresponding persisted field in `per_seed.csv`; R8, `heatmap_matrix.npy` has shape `(number_of_seeds,3)` and every cell equals the corresponding `heatmap_cells.csv` value in metric order `[n,mean,sample_std]`.
9. Implement two validation modes. `checksum_only` validates the manifest against `manifest.schema.json`, verifies file existence, parses every file according to its declared format and columns or dtype, checks declared row counts and matrix shape, and verifies SHA-256 hashes. `relational` first performs `checksum_only` and then evaluates R1-R8, returning all failed rule identifiers. A mutant is considered detected only when it passes `checksum_only` but fails at least one of R1-R8.
10. Generate 20 unmodified output sets `clean_00` through `clean_19` using run identifiers 0 through 19. Generate a separate pristine mutation base using run identifier 100. Copy `clean_00` byte-for-byte to `release_output/`. Validate every clean set with both modes.
11. Create 40 independent mutant sets by copying the pristine mutation base before each mutation. Use five target indices j=0 through 4 for each of eight mutation classes, yielding exactly 8 times 5 cases. Preserve CSV headers, column types, parseability, finite numeric values, NumPy dtype, and matrix dimensionality. After each mutation, regenerate all manifest metadata, including row counts, sizes, shapes, and SHA-256 hashes, so the altered content is fully consistent with its manifest at the integrity level.
12. Apply mutation class M1, `raw_value_only`, for each j: add exactly `5.0 + j/10` to the observation value at seed `S00j`, observation `O00j`, changing no aggregate or heatmap file.
13. Apply mutation class M2, `raw_seed_only`, for each j: change the `seed_id` of observation `(S00j,O00j)` to `S9j0`, where the resulting identifiers are `S900` through `S940`; change no other file. These identifiers remain syntactically valid strings and are distinct from existing seeds.
14. Apply mutation class M3, `per_seed_count_only`, for each j: increase `per_seed.n` for seed `S00j` by exactly 3, changing no other file.
15. Apply mutation class M4, `per_seed_mean_only`, for each j: increase `per_seed.mean` for seed `S00j` by exactly `0.5 + 0.1*j`, changing no other file.
16. Apply mutation class M5, `summary_only`, for each j: increase `summary.grand_mean` by exactly `0.25 + 0.05*j`, changing no other file.
17. Apply mutation class M6, `heatmap_csv_only`, for each j: increase the `heatmap_cells.csv` value for seed `S00j`, metric `mean`, by exactly `0.75 + 0.1*j`, changing no other file.
18. Apply mutation class M7, `matrix_only`, for each j: increase matrix cell `[j,2]`, the `sample_std` column for seed `S00j`, by exactly `1.0 + 0.1*j`, changing no other file.
19. Apply mutation class M8, `coordinated_derived_files`, for each j: increase the mean for seed `S00j` by exactly `0.6 + 0.1*j` in all three derived locations—`per_seed.mean`, the matching `heatmap_cells.csv` mean cell, and matrix cell `[j,1]`—while leaving `observations.csv` and `summary.csv` unchanged. This mutation is internally coordinated across the per-seed and heatmap representations but contradicts the raw observations.
20. For each clean and mutant set, record whether schema and parsing pass, whether checksum-only validation passes, whether relational validation passes, the failed rule identifiers, and elapsed validation time. Assert as an experiment precondition that all 40 mutants parse successfully and pass checksum-only validation after manifest regeneration. If this precondition fails, mark the run invalid rather than counting malformed or stale-manifest files as relational detections.
21. Save machine-readable aggregate results to `results/results.json`, including counts by mutation class, all individual outcomes, package-file audit results, software versions, and wall-clock time. Audit that the repository contains executable source, the four canonical release CSVs, `heatmap_matrix.npy`, a schema-valid versioned manifest, `requirements.lock`, and README documentation of `make reproduce`.
22. Create `results/detection_summary.png` at 1600 by 900 pixels. The left panel must show eight bars, one per mutation class, with detected count out of five and a dashed horizontal line at 4.5, representing the overall 90% target when aggregated. The right panel must show `relationally detected mutants`, `checksum-only detected mutants`, and `clean sets passed` as counts with denominators 40, 40, and 20 annotated above the bars. Include exact counts in bar labels.
23. Decide the hypothesis using no statistical resampling: it is supported if and only if at least 36 of 40 mutants pass checksum-only validation but fail one or more relational rules, all 20 clean regenerated sets pass relational validation, and the 40-of-40 mutant parse/checksum precondition holds. It is refuted if fewer than 36 mutants are relationally detected or if any clean set fails. Report an invalid experiment separately if any mutant fails parsing or checksum-only validation, because that would not test coordinated content-plus-manifest mutation.

## Metrics
- Relational mutation detection count and rate: number of the 40 mutants that pass checksum-only validation and fail at least one of R1-R8, reported as count and percentage; the support threshold is at least 36/40 or 90%.
- Clean acceptance count and rate: number of the 20 unmodified regenerated sets that pass schema, parsing, checksum, and every relational rule; the required result is exactly 20/20 or 100%.
- Checksum-only mutant detection count: number of mutants rejected before relational rules; the required precondition is 0/40 because every mutant receives freshly regenerated manifest metadata and hashes.
- Per-class detection count: detected mutants out of five for each of M1 through M8, used to reveal weak relational rule categories even when the aggregate threshold is met.
- Rule-level failure counts: for each R1 through R8, the number of mutants triggering that rule, allowing verification that detections arise from cross-file semantics rather than formatting.
- Artifact completeness audit: Boolean presence and validity checks for executable source, exactly four canonical release CSV files, the heatmap matrix, schema-versioned manifest, environment lock file, and documented `make reproduce` command.
- Wall-clock runtime: elapsed seconds for complete generation, mutation, validation, reporting, and figure creation; it must remain below 1800 seconds.

## Time budget
20 minutes (ceiling 30).

## Expected outcomes
- **If supported:** All 40 mutants remain format-valid and pass checksum-only validation, at least 36 of 40—expected 40 of 40 under the specified rules—fail relational validation, all 20 clean regenerations pass every rule, and the figure shows near-complete or complete detection across all eight mutation classes with zero checksum-only detections.
- **If refuted:** The hypothesis is refuted if 35 or fewer of the 40 checksum-valid mutants fail relational validation, or if even one of the 20 clean output sets fails relational validation; a mutant that fails parsing or checksum validation instead indicates an invalid implementation of the mutation precondition rather than support for relational detection.
