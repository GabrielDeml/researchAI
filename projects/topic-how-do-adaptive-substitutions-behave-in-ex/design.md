**Hypothesis:** For 80 paired source-and-output swaps that import a valid source-output pair from another unit while leaving the global artifact inventory unchanged and preserving successful transformation re-execution, an authenticated root committing only to the unordered artifact inventory will accept all 80 altered graphs, whereas an authenticated root also committing to canonical tuples of unit, operation, source edge, and output edge will reject all 80 and accept all 40 unmodified controls.

## Summary
Generate 40 deterministic transformation graphs and 80 behavior-preserving paired source-output swaps, then compare acceptance under artifact-inventory-only, relationship-committing, and unauthenticated self-declared roots.

## Protocol
1. Use Python 3.11 or later with only the standard library plus matplotlib and scipy; install them with `pip install matplotlib scipy`. Set matplotlib's backend to `Agg`. Set the sole pseudorandom generator to `random.Random(20250308)` and do not use any other randomness or timestamps.
2. Implement canonical JSON as UTF-8 bytes from `json.dumps(value, sort_keys=True, separators=(",", ":"), ensure_ascii=True)`. Implement every digest as lowercase hexadecimal SHA-256.
3. Implement four byte transformations: `reverse_v1(x) = x[::-1]`; `xor_a5_v1(x) = bytes(b ^ 0xA5 for b in x)`; `add_17_v1(x) = bytes((b + 17) % 256 for b in x)`; and `rol1_v1(x) = bytes(((b << 1) & 255) | (b >> 7) for b in x)`.
4. Generate 40 independent baseline graphs indexed `g = 0..39`. Each graph has 16 units indexed `u = 0..15`. Assign units 0-3 to `reverse_v1`, 4-7 to `xor_a5_v1`, 8-11 to `add_17_v1`, and 12-15 to `rol1_v1`. Set each unit ID to `g{g:02d}_u{u:02d}`.
5. For each unit, generate a unique 256-byte source. Its first 8 bytes are `g.to_bytes(4, "big") + u.to_bytes(4, "big")`; its remaining 248 bytes are consecutive `rng.getrandbits(8)` values. Compute the output by applying the assigned transformation.
6. Store every source and output as a separate artifact. Define an artifact ID as `sha256(b"artifact-v1\0" + kind.encode("ascii") + b"\0" + content).hexdigest()`, where kind is exactly `source` or `output`. Each artifact record contains `artifact_id`, `kind`, `size`, `content_sha256`, and base64-encoded content. Assert that all artifact IDs within a graph are unique.
7. Each unit record must contain exactly `unit_id`, `operation`, `source_id`, `output_id`, and a `context` object. The context contains `source_size`, `output_size`, `source_sha256`, and `output_sha256`, all derived from the currently referenced artifacts.
8. Define the unordered artifact-inventory root by projecting every artifact to `[artifact_id, kind, size, content_sha256]`, sorting these rows lexicographically by all fields, and computing `sha256(b"inventory-root-v1\0" + canonical_json(rows))`.
9. Define the relationship root by creating one tuple `[unit_id, operation, source_id, output_id]` per unit, sorting tuples lexicographically by `unit_id`, and computing `sha256(b"relationship-root-v1\0" + canonical_json({"inventory_root": inventory_root, "tuples": tuples}))`. This root therefore commits to both the inventory and the edge-labeled unit relationships.
10. For each baseline graph, save its inventory root and relationship root in a separate immutable trusted-roots object. Treat this object as authenticated out-of-band state: candidate graphs may not modify it. Also place a `declared_relationship_root` field in each candidate manifest; this field is not authenticated.
11. Create one unmodified control candidate from each baseline graph, for 40 controls total. Its declared relationship root equals the baseline relationship root.
12. Create two altered candidates from each baseline graph, for 80 altered graphs total. Alteration A exchanges both `source_id` and `output_id` between units 0 and 1. Alteration B independently starts from the baseline and exchanges both IDs between units 8 and 9. Each altered candidate therefore contains exactly one paired source-and-output exchange between units with the same operation.
13. After each exchange, recompute the context object of both affected units from their newly referenced artifacts. Do not change, add, remove, or reorder the artifact inventory. Recompute the candidate's relationship root and replace `declared_relationship_root` with that recomputed value, modeling unauthenticated manifest replacement. Do not change either trusted baseline root.
14. Implement common validation that: validates the stated schema and types; decodes every artifact; recomputes and verifies every artifact ID, size, and content hash; confirms all references resolve; recomputes and verifies every unit context field; reruns every unit's named operation on its referenced source bytes; and requires exact byte equality with its referenced output. Record common validation as passed only if every check passes for every unit.
15. Implement three root conditions, each combined with common validation. `AUTH_INVENTORY` accepts only if the candidate's recomputed inventory root equals the immutable trusted baseline inventory root. `AUTH_RELATIONSHIP` accepts only if the candidate's recomputed relationship root equals the immutable trusted baseline relationship root. `UNAUTH_RELATIONSHIP` accepts only if the candidate's recomputed relationship root equals the candidate-provided `declared_relationship_root`; it must not consult the trusted relationship root.
16. For every altered candidate, additionally assert and record: exact equality of the candidate and baseline artifact-record dictionaries; equality of their inventory roots; inequality of their relationship roots; successful re-execution of all 16 units; and exactly four changed edge fields relative to baseline, consisting of `source_id` and `output_id` in each of the two exchanged units.
17. Evaluate all three conditions on all 80 altered candidates and all 40 controls. Save one CSV row per candidate with graph index, candidate type, alteration, invariant results, common-validation result, all recomputed and trusted roots, and the three Boolean acceptance outcomes.
18. For `AUTH_RELATIONSHIP`, form the 2x2 table `[[altered accepted, altered rejected], [control accepted, control rejected]]` and run `scipy.stats.fisher_exact(table, alternative="less")`. Also report the acceptance-rate difference `control rate - altered rate`.
19. Create `acceptance_rates.png` as a grouped bar chart. The x-axis has `Unmodified controls (n=40)` and `Paired swaps (n=80)`; each group has bars for `Authenticated inventory`, `Authenticated relationships`, and `Unauthenticated relationships`. Plot acceptance proportions on a y-axis from 0 to 1, annotate every bar with its numerator, denominator, and proportion, and use a minimum size of 1200 by 700 pixels at 150 DPI.
20. Classify the hypothesis as supported only if all 80 alterations satisfy every invariant and common validation, `AUTH_INVENTORY` accepts exactly 80/80 alterations and 40/40 controls, `AUTH_RELATIONSHIP` accepts exactly 0/80 alterations and 40/40 controls, its acceptance-rate difference is exactly 1.0, and its one-sided Fisher exact p-value is below 0.001. Treat `UNAUTH_RELATIONSHIP` acceptance of 80/80 alterations and 40/40 controls as a required negative-control sanity check. Any failure of these exact count criteria refutes the stated hypothesis.

## Metrics
- Altered-graph inventory preservation: number of altered candidates whose complete artifact-record dictionary and inventory root exactly equal their baseline; required value is 80/80.
- Transformation re-execution success: number of altered candidates for which all 16 operations reproduce their referenced outputs byte-for-byte; required value is 80/80.
- Authenticated inventory-root acceptance: accepted candidates divided by candidates, reported separately for 80 alterations and 40 controls.
- Authenticated relationship-root acceptance: accepted candidates divided by candidates, reported separately for 80 alterations and 40 controls.
- Unauthenticated relationship-root acceptance: candidates whose recomputed root equals their replaceable declared root, reported separately for alterations and controls.
- Relationship-root acceptance-rate difference: control acceptance proportion minus altered acceptance proportion under AUTH_RELATIONSHIP; support requires exactly 1.0.
- One-sided Fisher exact test: use table [[altered accepted, altered rejected], [control accepted, control rejected]] under AUTH_RELATIONSHIP with alternative='less'; support requires p < 0.001.
- Mutation-shape validity: number of altered candidates with exactly four changed edge fields across exactly two units, no changed operation fields, and a changed relationship root; required value is 80/80.
