# Experiment design: Topic Can `make reproduce` be run from a fresh isolated checkout in a clean container or virtual machine, with the exact command, container or image identifier, interpreter path, exit status, stdout and stderr logs, generated hashes, and comparison against the released reference outputs reported? _(auto-enqueued follow-up from topic-can-a-complete-artifact-package-be-release)_

**Hypothesis:** Across six independent clean-container runs of `make reproduce`, a provenance capture harness will produce records containing the checkout revision, immutable image identifier, resolved interpreter path, literal command, integer exit status, separately hashed stdout and stderr logs, generated-file inventory, generated hashes, reference hashes, and per-output comparison results; an independent verifier will recompute and confirm every recorded field in all six records.

## Summary
Run six primary and six replay executions of the literal command `make reproduce` in fresh Docker containers and isolated checkouts, then independently verify 66 provenance checks and 18 generated-output byte comparisons.

## Protocol
1. Implement the experiment using host Python 3.11 or newer and only its standard library; optionally install `matplotlib==3.9.2` with `python -m pip install matplotlib==3.9.2` for the required PNG. Set the artifact random seed to 20250308. Do not access the network during preflight or timed execution. Supply the experiment package with an architecture-appropriate OCI image archive containing Linux, CPython 3.12, POSIX shell utilities, Git, and GNU Make, plus `image.lock.json` containing the archive SHA-256 and expected Docker image ID in the form `sha256:<64 lowercase hex digits>`. Treat this archive as the offline equivalent of a previously pulled immutable image.
2. Before starting either the experiment timer or any checkout, run an untimed fail-fast Docker preflight. Use the configured `DOCKER_HOST` if present; otherwise use the active Docker context. On macOS, run `open -a Docker` if `docker info` initially fails; on Linux with systemd, run `sudo -n systemctl start docker` if it initially fails. Poll `docker info` every 2 seconds for at most 120 seconds. If it still fails, report status `BROKEN_DOCKER_DAEMON` and execute no primary or replay runs.
3. Repair stale CLI plugins before the final `docker info`: inspect `${DOCKER_CONFIG:-$HOME/.docker}/cli-plugins/docker-dev` and `docker-feedback`; if either is a dangling symlink or is not executable, rename it by appending `.disabled`. Run `docker info` again. Confirm the runner can access the configured socket without an interactive privilege prompt by successfully running both `docker version` and `docker ps`. Any failure is `BROKEN_DOCKER_PERMISSION`, not a refutation.
4. Compute SHA-256 of the supplied OCI archive and compare it with `image.lock.json`. Inspect the expected image ID locally with `docker image inspect`. If absent, load only the supplied archive with `docker load`, then inspect again; never run an unpinned `docker pull`. Require the resulting `.Id` to equal the locked `sha256:` identifier exactly and require the image architecture to equal `linux/arm64` on Apple Silicon or the runner's declared Linux architecture. Run a smoke container with `--network none` that executes `python3 --version`, `git --version`, and `make --version`. Any archive, ID, architecture, or smoke-test failure is `BROKEN_IMAGE_PREFLIGHT`. Save the successful `docker info`, image inspection, and smoke-test stdout and stderr separately under `preflight/`.
5. Generate a synthetic Git artifact repository locally. Commit `Makefile`, `reproduce.py`, `reference/`, and documentation, then clone it as a local bare repository used by all runs. `make reproduce` must delete and recreate `generated/` and invoke `python3 reproduce.py`. `reproduce.py` must use `random.Random(20250308)` to create exactly 10,000 records. For record index `i` from 0 through 9999, draw `x = rng.randrange(0, 1000000)` and compute `y = (1103515245*x + 12345 + i) % 2147483648`. Produce exactly three files: `generated/samples.csv`, containing the UTF-8 header `i,x,y\n` and the 10,000 decimal rows with LF endings; `generated/summary.json`, containing `n`, `sum_x`, `sum_y`, and the SHA-256 of `samples.csv`, serialized as UTF-8 with sorted keys, separators `(',', ':')`, and one trailing LF; and `generated/histogram.bin`, containing 256 little-endian unsigned 32-bit counts of `x % 256`. It must print exactly `generated 3 files from 10000 records\n` to stdout, exactly `seed=20250308\n` to stderr, and exit 0.
6. Create the three files under `reference/` before the repository commit using a separate `build_references.py` implementation that does not import `reproduce.py`. Confirm once that the reference inventory is exactly `samples.csv`, `summary.json`, and `histogram.bin`. Commit the references and record the resulting artifact revision from `git rev-parse HEAD`. No run may modify the bare repository or reference files.
7. After all preflight steps succeed, start a 20-minute timed section. Create six primary directories named `primary-01` through `primary-06`. For each run, make a new local clone from the bare repository, detach at the recorded revision, and confirm `git status --porcelain` is empty before execution. Never reuse a checkout or container.
8. For each primary run, resolve the interpreter path in a separate probe container made from the same locked image by running `python3 -c 'import os,sys; print(os.path.realpath(sys.executable))'` with `--network none`; require one absolute path line. Then create a new artifact container with `docker create`, a unique name, `--network none`, `--cap-drop ALL`, `--security-opt no-new-privileges`, `--read-only`, a writable tmpfs at `/tmp`, the checkout bind-mounted read-write at `/work`, working directory `/work`, the locked image, and command arguments exactly `make` and `reproduce`. Record the human-readable literal command as exactly `make reproduce`, the Docker container ID, locked image reference, and inspected immutable image ID.
9. Execute each created primary container using `docker start --attach`, capturing stdout bytes directly to `evidence/primary-NN/stdout.log` and stderr bytes directly to `evidence/primary-NN/stderr.log` using distinct subprocess pipes; never merge the streams and never decode and re-encode them. Obtain the integer exit status from `docker inspect --format '{{.State.ExitCode}}' CONTAINER_ID`. Preserve the checkout and logs, then remove the stopped container.
10. For each primary run, write one canonical UTF-8 JSON record with sorted keys and a trailing LF. It must contain: schema version; run number; checkout revision; immutable image reference and image ID; container ID; resolved interpreter path; literal command `make reproduce`; integer exit status; separate SHA-256 and byte length for stdout and stderr; generated-file inventory as sorted relative paths and byte sizes; SHA-256 for every generated file; sorted reference-file inventory and SHA-256 values; and, for each expected output, generated hash, reference hash, byte equality, and hash equality. Inventory only regular files and reject symlinks, unexpected files, missing files, or paths outside `generated/` and `reference/`.
11. After all six primary runs, create six replay directories named `replay-01` through `replay-06`. Repeat Steps 7 through 9 from new clones and new containers, pairing replay NN with primary NN. Capture replay logs, exit status, interpreter path, inventories, and hashes in replay JSON files, but do not overwrite primary evidence. Thus the timed section must complete exactly six primary and six replay executions.
12. Implement `verify.py` independently: it may use only the standard library, must not import the harness, artifact generator, reference builder, or their helper modules, and must parse evidence from disk. For each of the six primary records, perform exactly 11 category checks: (1) checkout revision equals `git rev-parse HEAD`; (2) immutable image reference and image ID equal the lock and current `docker image inspect`; (3) the absolute interpreter path equals a newly resolved path from the locked image and the paired replay value; (4) literal command equals `make reproduce` and container command arguments recorded by the harness were `['make','reproduce']`; (5) primary and replay exit statuses are integers equal to 0; (6) recomputed primary stdout length and SHA-256 equal the record and replay stdout hash; (7) recomputed primary stderr length and SHA-256 equal the record and replay stderr hash; (8) recomputed sorted generated inventory equals the record and replay inventory; (9) recomputed generated SHA-256 mapping equals the record and replay mapping; (10) recomputed reference inventory and hashes equal the record and are unchanged in the replay; and (11) recomputed per-output byte/hash comparison booleans are all true and equal the recorded results. A category passes only if every assertion within it passes. This yields exactly 6*11 = 66 evidence checks.
13. Independently of the 66 category checks, compare the raw bytes of the three primary generated files with the corresponding paired replay files for each run. Count one comparison per file, yielding exactly 6*3 = 18 byte comparisons. Also require every primary generated file to equal its released reference counterpart byte-for-byte.
14. Have `verify.py` emit `verification.json` containing attempted, passed, and failed counts; individual failures; elapsed seconds; and final classification. It must emit `verification_summary.png`, at least 1000 by 600 pixels, with two bars labeled `Evidence fields` and `Replay bytes`, showing passed/required values with fixed axes of 0-66 and 0-18 or normalized percentages, and annotate the bars with `66/66` and `18/18` when successful. Use deterministic plotting settings and no timestamps in the figure.
15. Classify the hypothesis as `SUPPORTED` only if preflight succeeded, all 12 executions completed within the 20-minute timed section, all six primary and six replay exit statuses are 0, the verifier reports exactly 66 attempted and 66 passed evidence checks, exactly 18 attempted and 18 passed byte comparisons, all 18 primary-to-reference byte comparisons pass, and the PNG exists and is nonempty. If preflight succeeded but any execution, evidence check, replay comparison, or reference comparison fails, classify it as `REFUTED`. If Docker/image preflight fails, fewer than six primary and six replay runs are attempted because of infrastructure failure, the verifier cannot run, or the timed section exceeds 20 minutes, classify it as `BROKEN`, report completed and attempted counts, and do not interpret it as evidence against the hypothesis.

## Metrics
- Evidence verification rate: number of passed verifier categories divided by 66; support requires exactly 66/66 = 1.000.
- Replay byte agreement: number of byte-identical primary/replay file pairs across six runs and three outputs divided by 18; support requires exactly 18/18 = 1.000.
- Released-reference agreement: number of byte-identical primary/reference file pairs across six runs and three outputs divided by 18; support requires exactly 18/18 = 1.000.
- Execution completion rate: successful zero-exit executions divided by 12 total primary-plus-replay runs; support requires 12/12 = 1.000.
- Stream-separation integrity: all 12 executions must have independently stored stdout and stderr, with recomputed byte lengths and SHA-256 hashes matching their records; any merged, missing, or mismatched stream fails the associated evidence checks.
- Timed elapsed duration: wall-clock seconds beginning only after successful preflight and ending after verification and PNG creation; support requires no more than 1200 seconds.

## Time budget
25 minutes (ceiling 30).

## Expected outcomes
- **If supported:** Preflight succeeds; six primary and six replay containers finish with exit status 0; the independent verifier reports exactly 66/66 evidence checks, 18/18 primary-to-replay byte comparisons, and 18/18 primary-to-reference byte comparisons; all records contain the locked revision and image ID, one absolute interpreter path, literal command `make reproduce`, separate reproducible log hashes, and identical three-file inventories; `verification_summary.png` shows two full-height 100% bars.
- **If refuted:** After a successful preflight, at least one of the 12 executions has a nonzero status, at least one provenance field cannot be recomputed, the evidence result is below 66/66, the replay result is below 18/18, or the reference result is below 18/18; Docker daemon, permission, image, or timeout failures instead produce an explicit `BROKEN` classification and are not counted as refutation.
