# Experiment design: Genetic algorithms

**Hypothesis:** On a 64-bit Royal Road function with eight-bit blocks, population 64, one-point crossover, mutation rate 1/64, and seeds 0 through 29, a (μ+1) GA will generate at least 1.8 offspring attempts per cache-miss fitness evaluation, versus at most 1.2 for a generational GA; consequently, its median counted-evaluation advantage in reaching fitness 56 under cache-miss-only accounting will shrink by at least half when every attempted offspring, including cached duplicates, is charged to the 20,000-evaluation budget.

## Summary
Run paired seeded simulations of a steady-state (μ+1) GA and a generational GA on a 64-bit eight-block Royal Road function, then compare duplicate rates and target-hitting advantages under cache-miss versus attempted-candidate budgets.

## Protocol
1. Use Python 3.11 or later with NumPy and Matplotlib only. Set μ = 64, seeds = 0,1,...,29, target fitness = 56, and budget B = 20000. Run each algorithm separately for every seed using a fresh numpy.random.Generator(numpy.random.PCG64(seed)).
2. Represent each genotype as a length-64 NumPy uint8 array. Define eight consecutive blocks [0:8], [8:16], ..., [56:64]. Define Royal Road fitness f(x) = 8 times the number of blocks whose eight bits are all 1; thus fitness is in {0,8,...,64} and target attainment means f(x) >= 56.
3. Maintain one global memoization dictionary per algorithm-seed run, keyed by genotype converted to 8 packed bytes with numpy.packbits(x).tobytes(). On a new key, compute and store f(x) and increment the cache-miss counter. On an existing key, return the stored value without incrementing that counter. Caching changes accounting only, never the returned fitness.
4. Initialize a multiset population of 64 independently sampled genotypes, with every bit sampled by rng.integers(0,2,size=64,dtype=numpy.uint8). Process the 64 candidates in order through the cache. Count every initialized candidate as one attempted-candidate evaluation, including duplicate initial genotypes. Retain duplicates as separate population members. If a target genotype occurs during initialization, record the counters at its first occurrence, but still construct the complete population before ending the run.
5. Use the same parent-selection and variation operators in both algorithms. To select one parent, sample two population indices independently and uniformly with replacement using rng.integers(0,64,size=2); select the higher-fitness individual, choosing the first sampled index on a tie. Select two parents independently this way, so they may be identical. Always perform one-point crossover: sample c uniformly from integers 1 through 63 inclusive and create one child as parent 1 bits [0:c] followed by parent 2 bits [c:64]. Mutate each child bit independently with probability 1/64 by XOR with the mask rng.random(64) < 1/64. Each resulting child, even if identical to a parent or earlier genotype, is one offspring attempt.
6. For the (μ+1) GA, generate and evaluate one child at a time. After evaluation, if its fitness is at least 56, record target attainment immediately. Otherwise append it to the population, identify the minimum fitness among the resulting 65 members, choose one member uniformly at random from all members having that minimum fitness using the same RNG, and delete it, restoring population size 64.
7. For the generational GA, freeze the current 64-member population as the parent population and sequentially generate 64 children using selection only from that frozen population. Evaluate each child immediately and record target attainment immediately if its fitness is at least 56. If no child reaches the target, replace the entire parent population with the 64 children, without elitism, and begin the next generation. Cached duplicates remain separate population members.
8. Maintain four counters per run: init_attempts, fixed at 64 after initialization; init_cache_misses; offspring_attempts, incremented once for every generated child; and offspring_cache_misses, incremented only when a child genotype is absent from the cache. Define total attempted-candidate count C_attempt = init_attempts + offspring_attempts and total cache-miss count C_miss = init_cache_misses + offspring_cache_misses.
9. After initialization, continue each run until either a generated child first has fitness >= 56 or C_miss reaches 20000. A child that causes C_miss to become exactly 20000 is evaluated and may attain the target. Do not stop when C_attempt reaches 20000, because the same trajectory must also reveal performance under cache-miss-only accounting.
10. For each run, if the target is attained, record its C_miss and C_attempt. Define the cache-accounting hitting score S_miss as the recorded C_miss if C_miss <= 20000, otherwise 20001. Define the attempted-candidate hitting score S_attempt as the recorded C_attempt if C_attempt <= 20000, otherwise 20001. If no target is attained before the run stops at C_miss = 20000, set both scores to 20001. Thus 20001 is the preregistered penalty for failure under the corresponding 20000-count budget.
11. For duplicate production, compute pooled offspring attempt ratios over the 30 runs separately for each algorithm: R = sum(offspring_attempts) / sum(offspring_cache_misses). Use counters accumulated through target attainment or the C_miss = 20000 stopping point. Initialization is excluded from this ratio. Also retain each run's individual ratio for plotting; if a run has zero offspring cache misses, mark its individual ratio undefined but still use its counters in the pooled ratio.
12. For each seed and accounting rule, compute the paired advantage of (μ+1) over the generational GA as D_miss(seed) = S_miss_generational(seed) - S_miss_muplus1(seed) and D_attempt(seed) = S_attempt_generational(seed) - S_attempt_muplus1(seed). Positive values favor (μ+1). Define A_miss as the ordinary sample median of the 30 D_miss values and A_attempt as the ordinary sample median of the 30 D_attempt values; for an even sample, use the mean of the two central sorted values as implemented by numpy.median.
13. Declare the complete hypothesis supported if and only if all four preregistered conditions hold: R_muplus1 >= 1.8; R_generational <= 1.2; A_miss > 0; and A_attempt <= 0.5 * A_miss. Otherwise declare it refuted. Do not replace these decision thresholds with significance tests or exclude failed runs.
14. Save run_records.csv with one row per algorithm-seed run containing algorithm, seed, target_reached, target_C_miss, target_C_attempt, S_miss, S_attempt, initialization misses, offspring attempts, offspring cache misses, and individual offspring ratio. Save summary.json containing both pooled ratios, both median advantages, success counts under each accounting rule, the four Boolean conditions, and the final supported/refuted decision.
15. Save royal_road_accounting.png as a two-panel figure. In the left panel, plot the 30 individual offspring-attempt/cache-miss ratios for each algorithm with horizontal jitter, overlay each pooled ratio as a large marker, and draw dashed horizontal reference lines at 1.2 and 1.8. In the right panel, plot bars for A_miss and A_attempt, draw a dashed horizontal line at 0.5*A_miss, include a zero line, and label each bar with its numeric value. Use a fixed 1600-by-700-pixel canvas at 100 dpi and no randomized plotting operations.

## Metrics
- Pooled (μ+1) duplicate-production ratio R_muplus1 = total offspring attempts across seeds divided by total offspring cache misses across seeds; threshold for support is at least 1.8.
- Pooled generational duplicate-production ratio R_generational = total offspring attempts across seeds divided by total offspring cache misses across seeds; threshold for support is at most 1.2.
- Cache-miss-accounting median advantage A_miss = median over seeds of S_miss_generational minus S_miss_muplus1; it must be positive.
- Attempt-accounting median advantage A_attempt = median over seeds of S_attempt_generational minus S_attempt_muplus1; shrinkage is supported when A_attempt <= 0.5*A_miss.
- Target success counts for each algorithm under each 20000-count budget, where success requires the corresponding recorded hitting count to be at most 20000; report these descriptively but do not add them to the decision rule.

## Time budget
10 minutes (ceiling 30).

## Expected outcomes
- **If supported:** The pooled (μ+1) ratio is at least 1.8, the pooled generational ratio is at most 1.2, the cache-miss median paired advantage A_miss is positive, and charging all attempted candidates reduces the advantage to A_attempt no greater than half of A_miss; all four conditions must hold.
- **If refuted:** The hypothesis is refuted if the (μ+1) pooled ratio is below 1.8, the generational pooled ratio exceeds 1.2, the cache-miss median advantage is nonpositive, or the attempted-candidate advantage exceeds 50% of the cache-miss advantage.
