# Experiment design: Topic **Can all raw records be made auditable?** Publish machine-readable records for all 128 baseline cases and all 3,840 case–mutant pairs, including source and output archive hashes, parser outcomes, fixed-point outcomes, semantic bitsets or stable hashes of those bitsets, behavioral distances, and first counterexamples. Include both fresh-process payloads and cryptographic hashes for every published artifact. _(auto-enqueued follow-up from topic-can-test-generation-policy-equivalence-che)_

**Hypothesis:** In 128 seeded provenance attacks that swap valid same-type artifact references between case–mutant pairs while leaving each artifact and its ordinary payload hash unchanged, payload-hash verification alone will accept all 128 altered bundles, whereas a context-bound digest over unit identifier, stage name, ordered parent digests, payload digest, and schema version will reject all 128 and accept every unmodified bundle.

## Summary
Generate 128 deterministic Boolean-expression cases and 3,840 case–mutant pairs, then test whether 128 same-type output-reference swaps pass ordinary payload-hash verification but fail context-bound provenance verification while all unmodified bundles pass both.

## Protocol
1. Use Python 3.11 or newer, the standard library, and matplotlib only. Set PYTHONHASHSEED=0 for every process. Use SHA-256 via hashlib.sha256. Do not access the network except, if necessary, to run `pip install matplotlib` before the experiment.
2. Create a clean output directory with subdirectories `artifacts/`, `fresh_process/`, `records/`, and `figures/`. Implement canonical JSON as UTF-8 encoding of `json.dumps(value, sort_keys=True, separators=(',', ':'), ensure_ascii=False)` followed by exactly one newline. Hash the exact stored bytes, including this newline when present.
3. Define a Boolean-expression AST represented only by JSON arrays: variables are `["var", k]` for integer k in 0..7; unary expressions are `["not", child]`; and binary expressions are `[op, left, right]`, where op is one of `"and"`, `"or"`, or `"xor"`. Implement a recursive validator/parser that rejects any other representation and, on success, returns a recursively normalized AST with the same array structure.
4. Define `gen_ast(rng, depth)` exactly as follows: if `depth == 0` or `rng.random() < 0.25`, return `["var", rng.randrange(8)]`; otherwise choose `op = rng.choice(["not", "and", "or", "xor"])`; for `"not"` return `["not", gen_ast(rng, depth-1)]`, and for a binary operator return `[op, gen_ast(rng, depth-1), gen_ast(rng, depth-1)]`. Use Python's `random.Random`, not the module-global generator.
5. Generate 128 baseline cases indexed i=0..127. For case i, instantiate `random.Random(710000+i)` and call `gen_ast(rng, 4)` once. Assign the baseline unit identifier `case-{i:03d}/baseline`.
6. Generate exactly 30 mutants per case, indexed j=0..29, for 3,840 case–mutant pairs. Instantiate `random.Random(910000 + 30*i + j)`, generate `perturbation = gen_ast(rng, 2)`, set `op = ["and", "or", "xor"][j % 3]`, and define the mutant AST as `[op, baseline_ast, perturbation]`. Assign pair unit identifier `case-{i:03d}/mutant-{j:02d}`. The pair's baseline member is the original case AST and its candidate member is this mutant AST.
7. Implement Boolean evaluation with conventional truth tables. Enumerate all 256 assignments a=0..255, with variable x_k equal to `(a >> k) & 1`. Pack each expression's 256 outputs into 32 bytes: assignment a is bit `(a % 8)` of byte `a // 8`, with Boolean true represented by 1. Call this the semantic bitset, and compute its SHA-256 hexadecimal digest.
8. For every baseline and pair unit, compute parser outcomes for all source expressions. Each parser outcome must contain `success`, `error_code` (null on success), and `canonical_ast_sha256`. Test the parser/serializer fixed point by canonical-serializing the parsed AST, reparsing those bytes, serializing again, and setting `fixed_point=true` only if the two serialized byte strings are identical. For baseline units, set behavioral distance to 0. For pair units, compute behavioral Hamming distance as the number of differing bits between the baseline and mutant semantic bitsets and normalized behavioral distance as that count divided by 256.
9. Write a worker program that processes exactly one unit per invocation. Launch it with `subprocess.run` in a new Python interpreter for each of the 128 baseline units and 3,840 pair units, for 3,968 fresh processes total. Pass only the unit index/type and deterministic output paths as arguments; the worker must regenerate its inputs from the specified seeds rather than receiving in-memory Python objects. Capture exact stdout and stderr bytes. Require exit code 0 and empty stderr. The worker's stdout must be canonical JSON containing the unit identifier, source AST hashes, parser outcomes, fixed-point outcomes, semantic bitset hashes, behavioral distances, and paths of files it wrote. Save stdout unchanged as `fresh_process/<safe-unit-id>.json` and hash its exact bytes.
10. In each worker, create a deterministic source ZIP archive at `artifacts/<safe-unit-id>.source.zip`. A baseline source archive contains `baseline.json`; a pair source archive contains `baseline.json` and `mutant.json`. Store canonical JSON AST bytes. Create ZIP entries in lexicographic filename order using ZIP_STORED, timestamp `(1980,1,1,0,0,0)`, Unix mode 0644, no archive comment, and no extra fields. Compute the SHA-256 of the final archive bytes.
11. In each worker, create a deterministic output ZIP archive at `artifacts/<safe-unit-id>.output.zip`. It must contain `outcome.json`, `semantic_baseline.bin`, and `semantic_candidate.bin` in lexicographic order with the same fixed ZIP metadata. For baseline units, the candidate bitset equals the baseline bitset. `outcome.json` contains the unit identifier, parser outcomes, fixed-point outcomes, both semantic bitset hashes, Hamming distance, and normalized distance. Compute the SHA-256 of the final output archive bytes.
12. Use schema version string `audit-provenance-v1`. Define a context digest as SHA-256 of canonical JSON bytes for the object `{"ordered_parent_digests":P,"payload_digest":H,"schema_version":"audit-provenance-v1","stage_name":S,"unit_identifier":U}`, where U is the full unit identifier, S is the stage name, P is a JSON array preserving parent order, and H is the lowercase payload SHA-256. For each source archive, use stage `source-archive` and P=`[]`. For each output archive, use stage `output-archive` and P equal to a one-element array containing that unit's source-archive context digest.
13. After all workers finish, launch a separate fresh Python indexing process. It must independently hash every source archive, output archive, and captured fresh-process stdout payload, verify the reported outcomes by reading the archives, and write one canonical JSON line per unit to `records/raw_records.jsonl`, ordered first by case index, then with baseline before mutants, then by mutant index. Each of the 3,968 records must include unit identifier, record type, case and mutant indices, source/output/fresh-process paths and SHA-256 hashes, source and output context digests, ordered parent digests, schema version, parser outcomes, fixed-point outcomes, semantic bitset hashes, Hamming distance, and normalized distance.
14. Construct one unmodified bundle per unit. Each bundle contains the unit identifier and two artifact references. Each reference contains stage name, path, payload digest, stored context digest, ordered parent digests, and schema version. Thus there are 3,968 unmodified bundles covering all 128 baselines and all 3,840 pairs.
15. Implement payload-only verification as follows: for each referenced artifact, recompute SHA-256 from the bytes at its referenced path and accept that reference only if it equals the payload digest stored in that same reference. Do not inspect unit identifier, stage, parents, or schema. A bundle is accepted only if both references pass.
16. Implement context-bound verification as follows: first perform payload-only verification. Then, for each reference, recompute the context digest using the bundle's target unit identifier, the reference's stage name, the target bundle's ordered parent digests, the verified payload digest, and the schema version. Accept only if this recomputed digest equals the stored context digest. For an output reference, the target ordered parent list must contain the target bundle's source-reference context digest, not a parent supplied by a donor output artifact.
17. Verify all 3,968 unmodified bundles with both verifiers and store one machine-readable result row per method and bundle. Any unmodified rejection is an unexpected counterexample.
18. Create exactly 128 altered bundles, one per case. Select unit `case-{i:03d}/mutant-{(i % 30):02d}` for each i=0..127. Initialize `random.Random(20250308)`, shuffle the selected unit identifiers once, partition the shuffled list into 64 adjacent pairs, and within each pair exchange only the complete output-artifact reference. Leave each target's source reference and target unit identifier unchanged. Do not modify, copy, or reserialize any archive. The exchanged output references retain their original donor paths, payload digests, context digests, stage names, parent digests, and schema versions, so each artifact and its ordinary payload hash remain unchanged.
19. Verify all 128 altered bundles using both methods. Record target unit, donor unit, target source context digest, donor output payload digest, donor stored context digest, recomputed target context digest, and the accept/reject decisions in `records/attack_results.jsonl`.
20. Write `records/first_counterexamples.json` containing: (a) the first 10 altered bundles in target-unit lexicographic order as provenance-failure witnesses, including both verifier decisions and all compared digests; and (b) up to the first 20 unexpected deviations in lexicographic order, where a deviation is an altered bundle rejected by payload-only verification, an altered bundle accepted by context verification, or any unmodified bundle rejected by either verifier. Use an empty array when no unexpected deviations exist.
21. Compute aggregate counts and rates for the four cells: payload-only/unmodified, context-bound/unmodified, payload-only/altered, and context-bound/altered. Also report the number of unique source hashes, output hashes, semantic hashes, parser successes, fixed-point successes, and the mean, median, minimum, and maximum pairwise normalized behavioral distance. Write these data as canonical JSON to `records/metrics.json`.
22. Generate `figures/provenance_acceptance.png` at 1600x900 pixels using matplotlib. Plot four bars showing acceptance rate: unmodified payload-only, unmodified context-bound, altered payload-only, and altered context-bound. Use a y-axis from 0 to 1, annotate each bar with `accepted/total`, and use distinct colors for unmodified and altered conditions.
23. In a final fresh indexing process, enumerate every published payload artifact under `artifacts/`, `fresh_process/`, `records/`, and `figures/`, excluding the inventory itself, and write `records/artifact_inventory.jsonl` with path, byte length, and SHA-256 for every file. Hash the exact inventory bytes and print the resulting inventory root hash to stdout as the final run identifier. The inventory plus this printed root hash is the cryptographic publication manifest.
24. Declare the hypothesis supported only if all of the following exact thresholds hold: payload-only accepts 128/128 altered bundles; context-bound accepts 0/128 altered bundles; both verifiers accept 3,968/3,968 unmodified bundles; all 3,968 fresh worker processes exit successfully with empty stderr; every parser outcome succeeds; every fixed-point test succeeds; all independently recomputed artifact hashes match; and `first_counterexamples.json` contains zero unexpected deviations. If any condition fails, declare the hypothesis refuted and preserve the first deviations in the counterexample file.

## Metrics
- Altered payload-only acceptance count and rate: number of the 128 swapped-reference bundles whose referenced archive bytes match the payload digests carried by those references, divided by 128.
- Altered context-bound acceptance count and rate: number of the 128 swapped-reference bundles whose recomputed target-bound context digests equal the donor references' stored context digests, divided by 128.
- Unmodified payload-only acceptance count and rate: accepted unmodified bundles divided by 3,968.
- Unmodified context-bound acceptance count and rate: accepted unmodified bundles divided by 3,968.
- Context rejection coverage: number of altered bundles accepted by payload-only verification and rejected by context-bound verification, divided by 128.
- Hash audit completeness: number of independently verified source archives, output archives, and fresh-process payloads divided by the expected 11,904 files of those three per-unit types.
- Parser success count: successful parser outcomes divided by all parsed expressions; every baseline unit has one expression and every pair unit has two.
- Fixed-point success count: true parse-serialize-reparse fixed-point outcomes divided by all tested expressions.
- Behavioral distance distribution: mean, median, minimum, and maximum of the 3,840 mutant-versus-baseline normalized Hamming distances over 256 assignments.
- Unexpected-deviation count: altered payload-only rejections plus altered context-bound acceptances plus unmodified rejections by either verifier.
